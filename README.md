# 분기 실적 대시보드

## 왜 이렇게 나눴나 — 수집과 계산의 분리

지표를 하나 추가할 때마다 DART를 다시 부르면 30분씩 걸립니다. 그래서 원천 데이터를
**한 번만** 받아 `data/fundamentals_YYYYMMDD.json` 으로 저장해두고, 지표는 그 파일
위에서만 계산합니다.

```
수집 (느림, 가끔)                계산·렌더 (빠름, 자주)
┌────────────────┐          ┌──────────────────────┐
│ DART 분기보고서  │  ──json──> │ @metric 로 등록된 지표들 │ ──> dashboard.html
│ 시장 종가/시총   │           │ PBR PER ROE PSR ...   │
└────────────────┘          └──────────────────────┘
     collect                        render (수 초)
```

**"원할 때마다 열을 추가한다"는 요구가 바로 이 구조입니다.** 새 지표를 넣고
`render`만 다시 돌리면 됩니다. DART는 건드리지 않습니다.

## 실행

```python
%cd /content/company-screener
import os; os.environ["DART_API_KEY"] = "발급받은_키"

%run quarterly_dashboard.py all        # 수집 + 렌더 (첫 실행, 25~35분)
```

이후 지표만 바꿀 때는:

```python
%run quarterly_dashboard.py render     # 저장된 데이터로 페이지만 다시 생성 (수 초)
```

`dashboard.html` 이 만들어집니다. 파일 하나만 열면 되고 외부 인터넷이 필요 없습니다.
정렬(머리글 클릭), 검색, 열 고르기, CSV 저장이 페이지 안에서 동작합니다.

## 지표 추가하기

`metrics_custom.py` 에 함수를 쓰면 열이 하나 늘어납니다.

```python
from quarterly_dashboard import metric

@metric("PSR", desc="시가총액 / 최근 4분기 매출액", fmt="{:.2f}", better="low")
def psr(c):
    rev = c.ttm("매출액")
    return c.mcap / rev if rev and rev > 0 else None
```

`c` 로 쓸 수 있는 것들:

| | |
|---|---|
| `c.mcap` `c.price` `c.shares` | 시가총액(원), 종가, 상장주식수 |
| `c.equity` | 자기자본 (지배주주지분 우선, 없으면 자본총계) |
| `c.bs("자산총계")` | 재무상태표 계정 — 자산총계 / 부채총계 / 자본총계 / 지배주주지분 |
| `c.q("매출액")` / `c.q("매출액", 4)` | 최신 분기 / 4분기 전(전년 동기) 값 |
| `c.series("영업이익")` | 최신순 분기 값 목록 |
| `c.ttm("순이익")` | 최근 4분기 합계 (한 분기라도 비면 `None`) |
| `c.ttm_prev("매출액")` | 그 직전 4분기 합계 (YoY 비교용) |
| `c.yoy("영업이익")` | 최신 분기의 전년 동기 대비 증감률(%) |

계정: `매출액` `영업이익` `순이익` `지배주주순이익`
(더 필요하면 `quarterly_dashboard.py` 의 `IS_ACCOUNTS` 에 추가)

`@metric` 옵션: `fmt` 표시 형식, `better`(`"low"`/`"high"`) 정렬·색상 방향,
`default_on=False` 처음엔 숨김.

**값을 못 구하면 `None`을 돌려주세요.** 0으로 채우면 정렬이 망가집니다.
`None`은 `–` 로 표시되고 정렬 시 항상 아래로 갑니다.

## 기본 지표

`PBR` `PER` `ROE(%)` `영업이익률(%)` `매출성장률(%)` `영업이익 YoY(%)` `영업흑자 분기`
`부채비율(%)`(기본 숨김) — 그리고 `metrics_custom.py` 의 예시 `PSR` `PBR/ROE` `영업이익 연속증가`.

- **PER**은 최근 4분기 지배주주순이익이 적자면 계산하지 않습니다(공란).
- **PBR·ROE의 자기자본**은 지배주주지분 우선입니다(비지배지분 제외).
- 자기자본은 최신 **분기** 재무상태표, 손익은 **최근 4분기 합(TTM)** 기준입니다.

## 분기 실적을 구하는 방법

DART는 분기 손익을 **누계**로 줍니다. 분기 단독 실적은 차분으로 구합니다.

```
1Q누계 = Q1          Q2 = 반기누계 − 1Q누계
반기누계 = Q1+Q2      Q3 = 3Q누계 − 반기누계
3Q누계 = Q1+Q2+Q3    Q4 = 연간 − 3Q누계
```

각 보고서가 전년 동기 누계(`frmtrm_add_amount`)도 함께 담고 있어, 보고서 6건이면
2년치 8분기가 나옵니다. 직전 분기 누계가 없으면 그 분기는 만들지 않고 비웁니다
(추정값을 넣으면 조용히 틀린 지표가 됩니다).

# 코스피 밸류 스크리너

## 코스피 밸류 스크리너

시장이 제공하는 PBR을 그대로 쓰지 않고, **DART 재무제표의 자기자본**과
**현재 주가·시가총액**을 직접 비교해 PBR을 다시 계산하는 스크리너입니다.

- 파일: `kospi_value_screener.py` (구글 코랩에서 바로 실행 가능한 단일 파일)
- **1단계** — 자체 계산 PBR로 저평가 후보 추출
- **2단계** — 영업이익 5년·3년 연속 흑자 여부를 `Y`/`N` 컬럼으로 표시
  (기본은 **표시만** 하고 걸러내지 않습니다. 6-1 참고)

## 2. 처리 순서

| 단계 | 내용 |
|---|---|
| 1 | 코스피 전 종목의 종목코드·종목명·종가·시가총액·상장주식수·**시장PBR** 수집 (아래 2-1 참고) |
| 2 | 시가총액 **5,000억원 이상**만 남겨 후보 축소 (DART 호출 수를 줄이기 위함) |
| 3 | 후보 종목만 OpenDART `fnlttSinglAcntAll`로 **가장 최근 보고서**(분기 우선, 없으면 직전 연간)의 재무상태표를 받아 **자본총계**, **지배기업 소유주지분** 추출 |
| 4 | 자기자본 / BPS / 계산PBR / 괴리율 계산 |
| 5 | `0 < 계산PBR ≤ 1.0` 인 종목만 남기고 **계산PBR 오름차순** 정렬 |
| 6 | **[2단계]** 남은 종목의 영업이익 5년·3년 연속 흑자 여부를 판정해 컬럼 추가 후 CSV 저장 |

기준일자는 입력값을 **직전 영업일로 자동 보정**합니다(휴장일 대응).

### 2-1. 시장 데이터 소스 (중요)

2026년부터 `data.krx.co.kr`의 JSON 엔드포인트가 **로그인 세션을 요구**합니다.
`KRX_ID`/`KRX_PW` 없이 pykrx를 쓰면 빈 응답이 돌아와
`Expecting value: line 1 column 1 (char 0)`(JSON 파싱 실패)로 죽습니다.
pykrx 1.2.8이 KRX 로그인 기능을 추가한 것도 같은 이유입니다.

그래서 소스를 이중화했습니다. `MARKET_SOURCE` 상수로 고를 수 있습니다.

| 값 | 동작 | 시장PBR | KRX 계정 |
|---|---|---|---|
| `"auto"` (기본) | pykrx 시도 → 실패 시 대체 소스로 자동 전환 | 경로에 따라 다름 | 불필요 |
| `"pykrx"` | pykrx만 사용. 실패 시 조치 방법을 안내하고 중단 | ✅ | **필요** |
| `"fdr"` | 대체 소스만 사용 | ❌ (공란) | 불필요 |

**대체 소스**는 FinanceDataReader가 GitHub에 올려두는 일자별 KRX 상장종목
스냅샷 CSV입니다. KRX 로그인이 필요 없고 종가·시가총액·상장주식수를 모두 담고
있지만 **PBR은 없습니다.** 요청일에 파일이 없으면(휴장일) 하루씩 되감으며 찾습니다.

> 대체 소스로 돌아가면 `시장PBR`과 `괴리율(%)`만 공란이 되고,
> **계산PBR 스크리닝 자체는 완전히 동일하게 동작합니다.** 괴리율까지 필요하면
> KRX 홈페이지에 가입한 뒤 `KRX_ID`/`KRX_PW`를 설정하세요.

```python
import os
os.environ["KRX_ID"] = "krx아이디"      # 선택 — 설정하면 시장PBR·괴리율까지 나옵니다
os.environ["KRX_PW"] = "krx비밀번호"
```

### 보고서 선택 규칙

기준일 시점에 공시되었을 보고서를 **회계기간 종료일 기준 최신순**으로 나열하고,
앞에서부터 최대 4개까지 시도해 첫 번째로 성공한 보고서를 씁니다.

- 예) 기준일 2026-07-28 → `2026 1Q` → `2025 FY` → `2025 3Q` → `2025 2Q`
- 연결(CFS)을 먼저 조회하고, 없으면 별도(OFS)로 대체합니다.
- 아직 공시되지 않은 보고서를 종목마다 두드리는 낭비를 막기 위해,
  성공 0회 + 연속 실패 12회인 보고서는 "미공시"로 판단해 이후 조회에서 제외합니다.

라벨 표기: `2026 1Q`(1분기) / `2026 2Q`(반기) / `2026 3Q`(3분기) / `2025 FY`(사업보고서).

## 3. 계산식 정의

```
자기자본  = 지배기업 소유주지분        (있으면 이 값을 우선 사용)
          = 자본총계                  (지배주주지분이 없으면 — 주로 별도재무제표)

BPS       = 자기자본 / 상장주식수

계산PBR   = 시가총액 / 자기자본

괴리율(%) = (계산PBR - 시장PBR) / 시장PBR × 100
```

- **자기자본**: 연결 기준 자본총계에는 비지배지분(소수주주지분)이 섞여 있어
  주주가치를 과대평가합니다. 그래서 지배기업 소유주지분이 있으면 그 값을 씁니다.
- **시가총액·상장주식수**: `pykrx` 기준(보통주). 아래 4번의 우선주 주의사항 참고.
- **괴리율**: 양수면 자체 계산이 시장 PBR보다 비싸게 나온 것(= 시장 PBR이 더 낮음),
  음수면 자체 계산이 더 싸게 나온 것입니다. 괴리가 크다면 시장 PBR이 참조하는
  재무 기준일과 본 스크리너가 쓴 보고서가 다르거나, 연결/별도 기준이 다른 경우가 많습니다.
- 시장PBR이 결측(또는 0)인 종목은 괴리율을 `NaN`으로 두되 **결과에는 남깁니다**.

## 3-1. 2단계 — 영업이익 연속 흑자

1단계를 통과한 종목만 대상으로, **최근 5년/3년 영업이익이 연속 흑자인지** 판정합니다.
저PBR만으로는 "싼 이유가 있어서 싼" 기업(적자 지속, 사양산업)이 대거 섞이기 때문입니다.

### 판정 기준

| 값 | 의미 |
|---|---|
| `Y` | 해당 기간 **매년** 영업이익 > 0 |
| `N` | 한 해라도 영업이익 ≤ 0 (0도 흑자로 보지 않습니다) |
| `-` | 해당 연도 데이터가 없어 **판정 불가** (신규 상장, 보고서 미제출 등) |

`-`는 `N`과 다릅니다. "적자였다"가 아니라 "확인할 수 없다"는 뜻이니 직접 확인하세요.

### 호출 수를 아끼는 방식

DART 사업보고서 손익계산서는 한 응답에 **당기·전기·전전기 3개년**을 함께 담습니다.
그래서 5년치를 모으는 데 종목당 사업보고서 **2건**(예: `2025 FY` + `2022 FY`)이면 됩니다.
연도별로 5번 부르면 호출이 2.5배가 됩니다.

- 연결(CFS) 기준이며, 1단계에서 별도(OFS)를 쓴 종목은 **2단계도 별도**로 맞춥니다
  (`영업이익기준` 컬럼에 표시). 기준이 섞이면 비교가 무의미해집니다.
- 회계기준 변경 등으로 과거치가 재작성된 경우, **더 최신 보고서에 실린 값**을 씁니다.

### 표시만 할지, 걸러낼지

기본값은 **표시만** 합니다(`STAGE2_REQUIRE = ""`). 몇 개가 살아남는지 먼저 보고
기준을 정하라는 취지입니다. 통과 조건으로 바꾸려면:

```python
STAGE2_REQUIRE = "5년"   # 또는 "3년". 조건 미달은 '영업이익필터' 사유로 제외됩니다
```

2단계를 아예 끄려면 `STAGE2_ENABLED = False` (컬럼도 DART 호출도 생기지 않습니다).

> **연속 흑자 `Y`가 좋은 기업이라는 뜻은 아닙니다.** 이익의 질(일회성 손익, 매출 추세,
> 부채 수준)까지는 보지 않습니다. `영업이익추이(억)` 컬럼에 5년치 원값을 그대로
> 실어두었으니 직접 눈으로 확인하세요.

## 4. 결과 해석 시 주의사항

### 우선주가 상장된 종목 (`우선주존재 = Y`)

`pykrx`의 시가총액과 상장주식수는 **보통주 기준**인데, 자기자본은 보통주·우선주를
합친 회사 전체 값입니다. 따라서 우선주가 상장된 종목은

- 분자(시가총액)에서 우선주 시총이 빠져 **계산PBR이 실제보다 과소 계산**되고,
- 분모(상장주식수)에서 우선주 주식수가 빠져 **BPS가 과대 계산**됩니다.

이런 종목은 `우선주존재` 컬럼에 `Y`로 표시하니, 저PBR 상위에 올라왔다면
우선주 시총을 더해 다시 확인해야 합니다. (우선주 종목 자체는 분석 대상에서 제외합니다.)

### 금융지주·은행·보험·증권

자본 구조와 규제자본(BIS비율, K-ICS/RBC 등)의 성격이 일반 제조업과 완전히 다릅니다.
자산 대부분이 금융자산이라 장부가치가 이미 시가에 가깝게 평가되어 있고,
대손충당금·보험부채 할인율 가정에 따라 자기자본이 크게 흔들립니다.
**"PBR 1배 미만 = 저평가"라는 해석을 그대로 적용하면 안 되며**, 금융업종은
별도의 잣대(ROE, 자본비율, 배당성향)로 다시 검토해야 합니다.
이 주의사항은 스크립트 상단 주석에도 명시되어 있습니다.

### 실행 시간

DART 응답이 **종목당 6~7초**로 느려서, 순차 조회하면 시총 5,000억 이상 약 300종목에
30분 이상 걸립니다. 그래서 `DART_WORKERS`(기본 4)만큼 동시에 조회합니다.
호출 **총량은 그대로**이고 응답 대기 시간만 겹치므로 DART 일일 한도에는 영향이 없습니다.

| 설정 | 1단계(약 300종목) | 2단계(1단계 통과분, 종목당 2건) |
|---|---|---|
| `DART_WORKERS = 1` (순차) | 30~35분 | +30분 안팎 |
| `DART_WORKERS = 4` (기본) | 8~10분 | +5분 안팎 |

더 올릴 수 있지만 DART가 응답을 지연시키기 시작하면 오히려 느려집니다.
동시 실행 여부와 무관하게 결과·제외 사유는 완전히 동일합니다(테스트로 고정).

### 콘솔 요약

기준일자, 전체 상장종목 수, 시총 필터 통과 수, DART 호출 수, **최종 통과 종목 수**,
**제외 종목 수**와 사유별 집계를 마지막에 출력합니다. 진행률은 `tqdm`으로 표시됩니다.

## 7. 오류 진단 (디버깅)

### 7-1. DART 키가 꼭 필요한가?

- 1~2단계(pykrx 시장 데이터 수집, 시총 필터)는 **키 없이** 돌아갑니다.
- 3단계부터는 **키가 반드시 필요합니다.** 자기자본을 못 가져오면 계산PBR 자체가
  나오지 않으므로 우회할 방법이 없습니다.
- 발급: <https://opendart.fss.or.kr> 가입 → 인증키 신청 → **이메일 인증까지 완료**해야
  활성화됩니다. 발급 직후 몇 분간은 `010`(등록되지 않은 키) 응답이 올 수 있습니다.

### 7-2. `--selftest` — 어디서 깨졌는지 3단계로 좁히기

전체(수백 종목)를 돌리기 전에 이걸 먼저 실행하세요. 3~4번의 호출만 씁니다.

```bash
python kospi_value_screener.py --selftest      # 로컬
```
```python
%run kospi_value_screener.py --selftest        # 코랩
```

```
[진단 1/3] pykrx 시장 데이터 (DART 키 불필요)
[진단 2/3] DART API 키 & corpCode 조회
[진단 3/3] DART 재무상태표 조회 & 계정 파싱   ← 삼성전자로 실제 파싱까지 확인
```

**`[FAIL]`로 표시된 첫 단계가 원인**입니다. 1번이 실패하면 DART 키와 무관한
KRX 접속 문제이고, 2번이 실패하면 키 문제, 3번이 실패하면 보고서/파싱 문제입니다.

### 7-3. 부분 실행 옵션

```bash
python kospi_value_screener.py --limit 20              # 시총 상위 20종목만 (빠른 확인)
python kospi_value_screener.py --ticker 005930 000660  # 특정 종목만 상세 추적
```

- `--ticker`는 시총·우선주 필터를 건너뛰고, 해당 종목의 `corp_code`, 사용한 보고서,
  연결/별도, **자본총계·지배주주지분 원시값**을 그대로 찍어줍니다.
  "이 종목 PBR이 왜 이렇게 나왔지?"를 추적할 때 씁니다.
- 부분 실행 결과는 `debug_` 접두사가 붙은 파일로 저장되어 전체 실행 결과를 덮어쓰지 않습니다.
- 파일 상단 상수 `LIMIT_CANDIDATES`, `DEBUG_TICKERS`로도 같은 설정이 가능합니다
  (코랩에서 셀에 통째로 붙여넣어 쓸 때 편합니다).

### 7-4. 자주 나오는 오류

| 증상 | 원인과 대처 |
|---|---|
| `AttributeError: 'dict' object has no attribute 'strip'` (키 입력 중) | 코랩이 표준 `getpass`를 자체 구현으로 바꿔치기해 두는데, 브라우저 통신이 실패하면 문자열 대신 dict를 돌려줍니다. 입력창 대신 `os.environ['DART_API_KEY'] = '...'` 로 지정하세요. 최신 코드는 이 상황을 감지해 조치 방법을 안내합니다 |
| 실행할 때마다 키 입력창이 뜬다 | 한 번 입력하면 같은 세션에서는 환경변수에 저장되어 다시 묻지 않습니다. 세션이 바뀌면 코랩 시크릿에 등록해 두세요 |
| `corpCode 응답이 ZIP이 아닙니다` | 키가 틀렸거나 아직 미활성. 응답 본문에 실제 사유가 같이 출력됩니다 |
| `DART 오류 010 / 011 / 012` | 등록되지 않은 키 / 사용 중지된 키 / 허용되지 않은 IP. **즉시 중단**합니다 |
| `DART 오류 020` | 일일 20,000건 한도 초과. 다음 날 재시도하거나 `MIN_MARKET_CAP_KRW`를 올려 후보를 줄이세요 |
| 제외 사유가 전부 `DART조회` | 후보 보고서가 아직 미공시일 가능성. `--selftest`의 "보고서 후보" 줄을 확인하고, 필요하면 `BASE_DATE`를 과거 날짜로 바꿔 보세요 |

| `KRX 로그인 실패: KRX_ID 또는 KRX_PW ...` | pykrx가 import 시 찍는 안내 문구입니다. `auto`/`fdr` 모드에서는 **무시해도 됩니다** |
| `ProxyError` / `ConnectionError` / 타임아웃 | KRX·DART 서버 또는 네트워크 문제. 잠시 후 재시도. DART 호출은 3회까지 백오프 재시도합니다 |
| 시장PBR·괴리율이 전부 공란 | 대체 소스에는 PBR이 없습니다. 계산PBR·BPS·스크리닝은 정상이므로 결과 자체는 유효합니다 |
| 결과가 0종목 | 정상 동작일 수 있습니다. `..._excluded.csv`의 `단계` 컬럼 집계를 먼저 보세요 |
| 계산PBR과 시장PBR 괴리가 큼 | `기준보고서`·`재무제표구분`·`자기자본기준` 컬럼을 확인하세요. 연결/별도 차이나 기준 시점 차이가 대부분입니다. `우선주존재=Y`면 4번 참고 |

**로그에 API 키는 남지 않습니다.** `requests` 예외 메시지에는 요청 URL이 통째로
들어있어 `crtfc_key=...`가 그대로 노출되는데, 콘솔 출력과 제외 CSV 양쪽에서
`***REDACTED***`로 가립니다. 진단 로그를 그대로 복사해 공유해도 안전합니다.

- **KRX 로그인 미설정으로 pykrx가 죽었을 때 대체 소스로 자동 전환**되는지,
  그 경우 시장PBR·괴리율만 공란이고 나머지 결과는 동일한지
- **동시 조회(`DART_WORKERS`)를 켜도 순차 실행과 결과·제외 사유가 완전히 같은지**,
  그리고 응답 지연이 실제로 겹쳐 빨라지는지
- 코랩 `getpass`가 dict를 반환하는 상황에서 죽지 않고 조치 방법을 안내하는지
- **2단계**: 사업보고서 연도 선택(5년치를 2건으로 덮는지), 영업이익 계정 매칭
  (IS/CIS 우선순위, `충당금적립전영업이익` 같은 유사 계정 배제), `Y`/`N`/`-` 판정,
  `STAGE2_REQUIRE` 필터 동작, 2단계 비활성화

**검증되지 않는 것은 네트워크 왕복 하나뿐입니다.** 실제 KRX·DART 응답 자체는
`--selftest`로 확인하세요(7-2 참고).
